Spec for development

Map search enhancement

Extending the map's search box to accept National Grid References, easting/northing pairs, and latitude/longitude (decimal or degrees-minutes-seconds), alongside the existing place name and postcode search.

This feature could not be built as a clickable prototype. The map's search box is part of a shared component (@defra/interactive-map) built and maintained in a separate repository, so this page sets out the intended behaviour as a spec for a developer to implement, with example states shown as annotated images.

Try the low fidelity clickable prototype (try ST 58205 72708, 358205, 172708 or 51.4518, -2.6029).

Why this change

Today, the map's search box only matches place names and postcodes. Users who already have a precise location - for example from a site plan, surveyor's report, or GPS device - have no way to search by National Grid Reference, easting/northing, or latitude/longitude. They currently have to convert their coordinates to a place name or postcode first, or guess-and-check by panning the map.

Technical starting point

For whoever picks this up: the map's search box is rendered by the search plugin in the @defra/interactive-map package, consumed by the production fmp-app service. That plugin already supports a customDatasets option alongside its default osNamesURL (place name/postcode) dataset - each dataset has includeRegex/excludeRegex to decide which input it should respond to, and a parseResults function to shape results for the map. The existing place name dataset's excludeRegex already excludes grid reference and coordinate-looking input, which suggests this exact feature was anticipated but never built. This is the extension point to use, rather than replacing the search box.

Marker and label style

This ticket is about search, not the look of the marker or label. Coordinate results reuse whatever marker and label place name results use when this is built. Do not restyle them here.

The label style is owned by the postcode outline design spec, which updates the label for all search results (postcodes, place names and coordinates) at the same time.

  • If this ticket is built first, use the current pin and label. The postcode outline ticket will update them later
  • If the postcode outline ticket is built first, use its label style (grey with a white halo). Do not go back to the old style

Acceptance criteria

Draft - please review and refine before handing to development.

  1. If a user types a National Grid Reference (with or without spaces, for example SJ8632197947 or SJ 8632 1979), when they pause typing, then the search box shows one suggestion with the parsed grid reference as the label.
  2. If a user types a numeric easting/northing pair (comma or space separated, for example 433200, 342200), when they pause typing, then the search box shows one suggestion labelled with the easting and northing values.
  3. If a user types a decimal latitude/longitude pair (for example 53.4084, -2.9916), when they pause typing, then the search box shows one suggestion labelled with the latitude and longitude to 5 decimal places.
  4. If a user types a degrees-minutes-seconds latitude/longitude (for example 53°24'30"N 2°59'30"W), when they pause typing, then the search box shows one suggestion labelled the same way as the decimal format.
  5. If a user selects any coordinate-type suggestion, when it is applied, then the map pans and zooms to that location and shows the same marker and label as a place name match (see marker and label style).
  6. If a user types something that could be a place name or postcode (for example "Manchester" or "SW1A 1AA"), when they pause typing, then only the existing place name/postcode suggestions show - the coordinate formats must not interfere with this.
  7. Only a full National Grid Reference (two-letter prefix plus a complete easting and northing, for example SJ8632197947) is treated as a grid reference - agreed with development to avoid ambiguity with postcode prefixes. Anything shorter falls through to the place name/postcode dataset as normal.

Edge cases

  • Grid reference or easting/northing resolves to a location outside Great Britain's National Grid - show the no-match state rather than an error page
  • Latitude/longitude resolves to a location outside Great Britain - show the no-match state, since the map only covers England
  • Partial or incomplete grid references (for example SJ86, a 100km square only) - treat as not yet a valid match rather than guessing a location
  • Grid reference vs postcode prefix ambiguity (for example two letters followed by a short number) - resolved: only a full NGR is accepted, so a short input like this always falls through to the place name/postcode dataset. Confirmed with development; review again after user testing in case it needs revisiting
  • Latitude/longitude with mismatched or missing compass directions (for example a bare 53.4, -2.9 with no N/S/E/W) - decimal format already covers this as signed numbers, so no direction letters are required
