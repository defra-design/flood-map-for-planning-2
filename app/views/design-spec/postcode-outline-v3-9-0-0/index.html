Spec for development

Postcode outline on search

When a user searches for a postcode, outline the postcode area on the map with a dashed line and lightly tint the map outside it, instead of dropping a pin at the centre of the postcode. Keep the search box open with the location in it, so users can see that clearing the search removes the outline.

This feature could not be built as a clickable prototype. The map, including its search and marker, is a compiled bundle of the shared @defra/interactive-map component built in the separate fmp-app repository, so this page sets out the intended behaviour as a spec for a developer to implement, with an illustrative mock-up.

Try the low fidelity clickable prototype (search for BS1 5AH).

Why this change

In the v3.8.0.0 research round, users who noticed the postcode pin found it helpful, but:

  • the pin and label cluttered the map and got in the way of seeing the site
  • the pin could be mistaken for the centre of the user's site, when it is only the centre of the postcode
  • users expected to be able to remove it, and assumed it would go away when they started drawing a boundary

Clearing the search already removes the pin. But the search box closes as soon as a result is selected, so users cannot see the location they searched for, or that deleting it would remove the pin.

Outlining the postcode area shows users where their search landed without covering the map, and makes it clearer that the result is a postcode area rather than a precise site location. This follows the pattern users already know from Google Maps, which outlines a searched postcode with a dotted line and lightly tints the map around it.

Keep the search open with the location in it

After a user selects a search result, the search box stays open instead of closing back to the "Search" button. It shows the selected location (for example "BS1 5AH, City of Bristol") until the user deletes it. This makes it clear what the map is showing, and that deleting it from the search box will remove the outline.

This applies whenever the map is showing a search result: the postcode outline, or the pin for a place name.

  • The search box stays open while the user clicks, pans or zooms the map
  • Deleting the text, or selecting the cross in the search box, clears the search and removes the outline, tint and label (or the pin for a place name)
  • While a location is showing, the cross clears the search, so its accessible name should be "Clear search" rather than the current "Close search"
  • Once cleared, the search box stays open and empty, showing the placeholder text, ready for a new search
  • Starting to draw a boundary also clears the search and removes the outline, tint and label

Visual design

Postcode outline styles
Element Style
Outline 3px dashed line in GOV.UK black #0b0c0c, 8px dash and 5px gap, round joins
Outline halo 6px solid white #ffffff line drawn under the dashes, so the outline stands out on light base map and dark blue flood zones
Tint outside the postcode #0b0c0c at 20% opacity, covering the map outside the postcode area
Inside the postcode No tint or fill, so the map inside reads at full brightness
Label The existing search result label (for example "BS1 5AH, City of Bristol"), in its current style (white #ffffff text on dark grey #393f42), with a 2px white #ffffff halo added around it. Centred horizontally above the top of the outline, with a 12px gap between the halo and the outline so there is room for the focus style. It sits above the tint and outline. This style applies to every search result label: postcodes, place names, and coordinates from the map search enhancement
Label contrast Text against the label background is 10.6:1. The grey label stands out against the light and tinted base map (at least 6:1), and the white halo stands out against the dark blue flood zones (about 7:1), so the label is clear wherever it sits. Without the halo, the grey label is only 1.5:1 against flood zone 3
Dark map style Swap the outline to white dashes with a black halo, and tint with #000000 at 30%. To be checked against the dark base map

Layer order

The tint sits under the flood data layers, and only covers the base map outside the postcode and outside any flood data shapes. This means flood zone (including climate change) and surface water colours are never changed by it and still match the key. The outline sits above the flood data layers, so it stays visible when a postcode is inside a flood zone.

From top to bottom:

  1. Map controls, panels and the postcode label
  2. User's drawn boundary
  3. Postcode outline (dashed line and halo)
  4. Flood data layers (flood zones 2 and 3, climate change flood zones, surface water, map features)
  5. Postcode tint (the base map outside the postcode and flood data)
  6. Base map

The flood data layers are partly see-through, so a tint placed underneath them would show through and change their colours. A tint with only the postcode cut out of it is not enough: the flood data shapes must be left untinted too. Darkening the base map in any other way has the same problem, because the base map shows through the flood data.

One way to build this is a single "inverted" polygon: a rectangle covering the whole map, with the postcode shape and the visible flood data shapes cut out as holes, filled at 20% opacity. The flood data shapes change with the selected dataset and climate change scenario, so the holes must be updated whenever these change.

However it is built, the flood data colours must look exactly the same as they do without the postcode outline.

Label with keyboard focus

The label can receive focus (for example to read it out), and uses the same focus style as the map's other buttons: a 4px black #0b0c0c border with a 3px yellow #ffdd00 ring outside it. The focus style sits outside the label's white halo, and must be visible the whole way round the label.

Data source

The map's search currently uses the OS Names API. For a postcode, this returns a single centre point and a bounding box (MBR_XMIN, MBR_YMIN, MBR_XMAX, MBR_YMAX), but not the shape of the postcode area. This is why the map can currently only show a pin.

To draw the outline, the service needs postcode boundary polygons. The likely source is OS Code-Point with Polygons, which is available to public sector bodies under the Public Sector Geospatial Agreement (PSGA). The team should confirm the Environment Agency's access and licence terms with the data team before development.

If a boundary is not available for a postcode (for example a newly created postcode), fall back to the current behaviour: zoom to the bounding box and show the pin.

Acceptance criteria

  1. If a user searches for a full postcode and selects it, when the result is applied, then the map zooms to fit the postcode area with padding around it, and shows the dashed outline and the tint outside it.
  2. If a user searches for a full postcode, when the outline is shown, then no pin is shown, and the postcode label is shown centred above the outline.
  3. If a postcode area is inside or overlaps a flood zone or surface water area, when the outline is shown, then the flood data colours inside and outside the outline are exactly the same as without the outline.
  4. If a postcode area is made of more than one separate part, when the outline is shown, then every part is outlined and left untinted.
  5. If a user searches for a place name (for example a town or village), when the result is applied, then the map shows the pin as it does now with the label in the new style (grey with a white halo), with no outline, and the search box stays open with the place name in it.
  6. If a user selects a search result, when the result is applied, then the search box stays open and shows the selected location.
  7. If a search result is showing, when the user clicks, pans or zooms the map, then the search box stays open with the location still in it.
  8. If a user deletes the location from the search box, or selects the cross, when the search is cleared, then the outline, tint and label (or the pin for a place name) are all removed, and the search box stays open and empty.
  9. If a search result is showing, when a screen reader user reaches the cross in the search box, then it is announced as "Clear search".
  10. If a user searches for a different location, when the new result is applied, then the previous outline, tint and label are replaced.
  11. If a user starts drawing a boundary (add polygon, add square or upload), when drawing begins, then the outline, tint and label are removed so they do not get in the way of the user's own boundary, and the search box is cleared so it no longer suggests a location is being shown.
  12. If no boundary is available for a postcode, when the result is applied, then the map falls back to the current pin behaviour.
  13. If a screen reader user selects a postcode result, when the outline is shown, then the existing search announcement confirms the map is showing that postcode.
  14. If a keyboard user tabs to the postcode label, when it receives focus, then it shows the label focus style (a 4px black border with a 3px yellow ring outside the label's white halo, visible the whole way round), and screen readers read out the label text.

Edge cases

  • Large rural postcodes may cover a big area - zoom to fit the whole postcode, even if that means zooming further out than the current postcode zoom level
  • Very small postcodes (for example a single building) - keep a minimum zoom so the user still sees enough of the surrounding area
  • Postcodes partly outside England - outline the whole postcode, as the flood data stops at the border anyway
  • Users may mistake the postcode outline for their site boundary - the outline style must look clearly different from a drawn boundary (dashed and black, rather than the solid boundary style)

To test in research

  • With and without the label - the current label had mixed feedback, as it confirms what was searched but can clutter the map
  • Whether 20% tint gives enough focus without making the base map hard to read
  • Whether keeping the search open with the location in it makes it clear to users how to remove the outline

If this does not work

If research shows that keeping the search open is not enough for users to see how to remove the outline, a further design to consider is a close button inside the postcode label. This is a separate design and is not part of this spec.
