Skill 7: Edit a user flow

Add, remove or reorder steps and journeys in a version's user flow, update links, add pages outside the main flow, or add a new screen type

This skill is in discovery. The workflow below is a starting point for exploring how it could work, and may change.

@copilot #edit-user-flow

When to use it

  • A page has been added to, or removed from, a journey
  • You want to show an alternative route as a new journey
  • A live or prototype address has changed
  • A help or guidance page needs adding under “Pages outside the main flow”
  • None of the screen types looks like a new page

Describe the change in your own words, for example: “add a contact details step after the results page in the main journey”.

For how user flows work, see How to use the user flows.

Five-step workflow

Step 1: Read the current journeys

Reads the journeys and otherPages lists at the top of the version's user-flow.html. Asks which journey you mean if a page appears in more than one.

Step 2: Make the change
  • Adds, removes or reorders steps and journeys
  • Uses a choice step when the user picks one of several screens and then rejoins the journey, instead of repeating steps in a new journey
  • Picks the closest screen type for a new step
  • Checks a prototype page exists before linking to it
  • Only adds a live address if you give it – it never guesses
  • Keeps commas and quote marks correct so the page still loads
Step 3: Add a new screen type (only if asked)

Screen types are in a shared file used by every version's user flow, so the skill checks with you first. It then:

  • draws the new screen for desktop and mobile using the existing wireframe parts
  • checks it fits inside the screen frames
  • adds it to the list of screen types, so it shows on every user flow and on the guide’s screen types page
Step 4: Check the page loads

Opens the user flow in the running prototype and checks the change in the desktop and mobile views.

Step 5: Summarise

Lists what changed, and any steps still missing a prototype link or live address.

Open questions

Things we're still exploring:

  • Could the skill build journeys from a description, like a research plan or a Mural board?
  • Should it flag prototype links to pages that no longer exist every time it runs?
  • Should journeys live in a separate data file so they're easier to edit and share between versions?
  • When a page changes, should every version's user flow be updated, or only the current one?
  • Do we need a screen type for every page, or would a general type with options work better?
