Skill 6: Create a user flow for a new version

Copy the previous version's user flow into a new prototype version and update its links, as part of creating a new version

This skill is in discovery. The workflow below is a starting point for exploring how it could work, and may change.

@copilot #create-user-flow

When to use it

  • After running Skill 1: Create a new prototype version
  • When a version doesn't have a user flow yet

To change the journeys in a user flow, use Skill 7: Edit a user flow. For how user flows work, see How to use the user flows.

Eight-step workflow

Step 1: Find the user flow to copy

Uses the newest version that has a user-flow.html file, currently v3-8-0-0.

Step 2: Copy it into the new version

Copies it to app/views/v3-9-0-0/user-flow.html. No route is needed – the Prototype Kit shows it at /v3-9-0-0/user-flow automatically.

Step 3: Check the prototype links
  • Checks each prototype page exists in the new version folder
  • Clears the link (but keeps the step) if the page doesn't exist
  • Leaves links to other versions, like /v3-7-0-2/upload, and lists them
  • Doesn't change live addresses
Step 4: Add a user flow link to the version card

Adds a “View v3.9.0.0 user flow” link to the version's card on the home page, after the prototype link.

Step 5: Update versions.json 
"userFlowUrl": "/v3-9-0-0/user-flow"
Step 6: Update the Related links

Points the User flow link under Related links and information on the home page at the new version. Asks first, in case you want it to keep pointing at the older version for now.

Step 7: Check the page loads

Opens the new user flow in the running prototype, or checks the file for typing mistakes like missing commas.

Step 8: Summarise

Lists which prototype links were cleared and which link to other versions, so you know what to update.

Files it changes

File Change
app/views/v3-9-0-0/user-flow.html New – copied from the previous version
app/views/index.html User flow link on the version card, Related links updated
app/views/versions.json userFlowUrl added

Open questions

Things we're still exploring:

  • Should creating a new version always create a user flow, or offer it as an option?
  • Should journeys be copied unchanged, or should the skill ask which journeys changed in the new version?
  • Should the screen designs and styles move into a shared file, so each version only holds its journeys?
  • Could the skill fill in prototype links by matching page names in the new version?
  • Should the home page User flow link always point to the newest version?
