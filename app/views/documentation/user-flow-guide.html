How to use the user flows

A user flow shows every screen in a journey through the service as a small wireframe, with the live and prototype address of each page.

Reading a user flow

Each grey box is one journey. The screens in a journey are shown in order, joined by arrows.

Under each screen you'll see:

  • Live – the address of the page on the live service (plain text, not a link)
  • Prototype – a link to the page in this prototype, if there is one
  • a short note, if one has been added

Select the screen title to open that page in the prototype.

Use the buttons at the top of the page to:

  • show desktop screens, mobile screens, or both – the page remembers your choice
  • print the user flow, with each journey kept on one page where possible

Pages that sit outside the journeys, such as help pages, are in a dashed box at the bottom under Pages outside the main flow. Each one lists the pages that link to it.

Where the user flow lives

Each prototype version has its own user flow file. For version 3.8.0.0 it is:

app/views/v3-8-0-0/user-flow.html

and you can view it at /v3-8-0-0/user-flow.

Everything you need to change is in two lists near the top of the file:

  • journeys – the journeys and their steps
  • otherPages – pages outside the main flow

You should not need to change anything below these lists.

Adding or changing a step

Each step is one line inside a journey's steps list:

{ "type": "radio", "title": "Triage page", "live": "/triage", "prototype": "options-radio", "note": "Optional note" },
What each part of a step does
Field What it does Needed?
type Which wireframe to show – see screen types Yes
title The label above the screen Yes
live The page's address on the live service, shown as plain text No
prototype The page in this prototype – shown as a link, and the title links to it too No
note A short note shown under the screen No

If you do not need a field, leave it out or leave it empty, for example "prototype": "". It will not be shown.

To add a step, copy an existing line and change it. Steps are shown in the order they appear in the list.

Every step except the last one in a list must end with a comma.

Adding a journey

Use a new journey to show an alternative route, such as a different way of adding a site boundary. Copy an existing journey block, give it a new heading and change the steps:

{
  "heading": "Upload a boundary",
  "steps": [
    { "type": "map",     "title": "Flood map",          "live": "/map",    "prototype": "map" },
    { "type": "upload",  "title": "Upload a boundary",  "live": "/upload", "prototype": "upload" },
    { "type": "results", "title": "Flood risk results", "live": "/results?[polygonstring]", "prototype": "results" }
  ]
},

Journeys are shown in the order they appear in the list. Put a comma between journey blocks, but not after the last one.

Pages outside the main flow

Some pages are not part of a journey but can be reached from several places, like the help page. Add these to the otherPages list.

They use the same fields as steps, plus from – a list of the pages that link to it:

{
  "type": "content",
  "title": "How to use this data",
  "live": "/how-to-use-flood-map-for-planning-data",
  "prototype": "how-to-use-flood-map-for-planning-data",
  "from": ["Full screen map (info panel)", "Help page", "Results page"]
},

These pages are shown without arrows, because they are not in a set order.

Screen types

Choose the type that looks most like the page. To see all of them as wireframes, open Screen types you can use at the bottom of the user flow page.

If you use a type that is not in this list, a plain page is shown instead.

Linking to prototype pages

The prototype address can be written in two ways:

  • without a slash at the start, like "map" – this links to the page in the same version folder as the user flow, for example /v3-8-0-0/map
  • with a slash at the start, like "/v3-7-0-2/upload" – this links to that exact address, so you can link to a page in another version

The live address is only ever shown as text, so it can include placeholders, such as /results?[polygonstring].

Making a user flow for a new version

  1. Copy user-flow.html from the previous version's folder into the new version's folder, for example app/views/v3-9-0-0/.
  2. Update the steps for anything that has changed in this version.
  3. Check that the prototype addresses point to pages that exist in the new version.
  4. On the prototype home page, add a “View user flow” link to the new version’s card, and update the User flow link under Related links and information so it points to the new version.
  5. Add "userFlowUrl" to the version’s entry in app/views/versions.json, for example "userFlowUrl": "/v3-9-0-0/user-flow".

If the page does not load

The user flow is built from the lists at the top of the file, so a small typing mistake in them can stop the page loading. Check for:

  • a missing comma between steps or journeys
  • an extra comma after the last step or journey in a list
  • a missing " quote mark around a value
  • a missing {, }, [ or ] bracket

The error in the terminal where the prototype is running usually gives the line number of the problem.
